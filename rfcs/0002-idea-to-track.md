# RFC 0002 — «Из идеи»: одно поле ввода, промты пишет локальная модель

Статус: принят; фазы 1–3 реализованы в ветке `feat/stable-audio-3`. Фаза 3: на странице «Из идеи» выбор движка — ACE-Step, YuE2 (только песня: теги стиля по правилам страницы YuE2 и текст по секциям) и Stable Audio 3 (только инструментал: родные инструкции Stable Audio без классификатора, `medium` или `small-music`, длительность из `Length:` в ответе); трек подписывается идеей. Проверено вживую: трек каждого из трёх движков из одной страницы. Фаза 2: страница `/idea` (`frontend/src/views/idea/IdeaPage.vue`) и вход с главной; промт для ACE-Step по умолчанию пишет помощник, а не модель ACE-Step (раздел 8). Фаза 1: `external/prompt-assistant`, `backend/app/assistant.py`, раздел «Помощник» на странице «Модели», шаги в setup-скриптах и desktop. Отступление от раздела 4.3: инструкции Stable Audio перенесены как есть (`prompt_assistant/sa3_prompts.py`) и отвечают текстом, а не JSON, — так их писали под модель; темп и длительность разбираются из хвоста `BPM: N. Length: N seconds`. Устройство «авто» — видеокарта, только пока не запущен ни один движок; при запуске движка помощник с видеокарты уходит. Устройство «видеокарта» — помощник занимает её как движок: работающий движок выгружается перед промтом, а «Сгенерировать» убирает помощника и запускает музыкальную модель (проверено: ACE-Step → помощник на видеокарте, промт за 7,9 с вместе с выгрузкой → ACE-Step снова).

## 1. Зачем

У каждого движка свой язык промтов. ACE-Step ждёт описание стиля, текст с метками `[Verse]` / `[Chorus]`, темп и тональность. YuE2 ждёт строку тегов жанра и размеченный текст песни. Stable Audio 3 ждёт теги в духе Freesound вроде `TrackType: Music, VocalType: Instrumental, …`. Чтобы получить хороший результат, нужно знать все три формата.

Цель — режим, где пользователь пишет только идею или смысл песни и выбирает «песня» или «инструментал». Промт в формате нужного движка пишет локальная языковая модель, затем приложение само запускает генерацию. Всё остаётся на компьютере пользователя, как и остальная Remiqora.

Что уже есть и на что опираемся:

| Движок | Свой помощник промтов | Что выдаёт |
|---|---|---|
| ACE-Step 1.5 | Есть: его языковая модель 5Hz LM, `POST /v1/create_sample` (Simple Mode из его Gradio). Remiqora это API пока не вызывает. | `caption`, `lyrics` со структурой, `bpm`, `keyscale`, `duration`, `timesignature`, `vocal_language` |
| Stable Audio 3 | Есть в апстриме: `stable_audio_3/interface/reprompt.py`, модель `Qwen/Qwen3.5-2B`, инструкции `Classifier`, `Music`, `Instrument`, `One-shot`, `SFX` | строка тегов с префиксом `TrackType: …` |
| YuE2 | Нет | — (нужны `style` и `lyrics` с метками секций) |

Режим «Просто» на странице ACE-Step уже принимает фразу (`sample_query` в `release_task`), но промт там пишется внутри генерации: пользователь его не видит, поправить не может, а сохранить удачный текст можно только из готового трека.

## 2. Принципы

1. **Одно поле — главный вход.** Режим не требует знать движки. Выбор движка есть, но с рекомендацией по умолчанию, и его можно не трогать.
2. **Промт виден и редактируем.** Результат помощника показывается карточками до генерации. Режим «сразу», без правки, — опция, а не единственный путь.
3. **Свой формат каждому движку.** Для ACE-Step промт пишет его собственная модель: формат гарантированно тот, что он понимает. Для Stable Audio и YuE2 — общий помощник с отдельной инструкцией на каждый движок.
4. **Помощник не отнимает видеопамять у движка.** По умолчанию работает на процессоре отдельным процессом, по образцу сервера сэмплов на CPU (`backend/app/sfx_cpu.py`).
5. **Ничего нового для скачивания без нужды.** Qwen3.5-2B тот же, что у помощника Stable Audio, и у многих уже лежит в кэше Hugging Face. Модели помощника скачиваются и удаляются на странице «Модели», как веса движков.
6. **Результат ложится туда же, куда и сейчас.** Трек появляется в ленте страницы движка и в библиотеке с теми же параметрами, что при ручной генерации. Отдельного хранилища у режима нет.

## 3. Как это выглядит

```
┌ Из идеи ───────────────────────────────────────────────────────────┐
│ ( Песня ) ( Инструментал )                     Язык: авто ▾         │
│ ┌────────────────────────────────────────────────────────────────┐ │
│ │ песня о том, как уезжаешь из маленького города ночным поездом  │ │
│ └────────────────────────────────────────────────────────────────┘ │
│ Чем сгенерировать:                                                 │
│  [● ACE-Step — быстро, рекомендуем]  [○ YuE2 — целая песня]        │
│                                       [Написать промт ✦]  □ сразу   │
├────────────────────────────────────────────────────────────────────┤
│ Стиль:  indie folk, melancholic, acoustic guitar, male vocal, …  ✎ │
│ Текст:  [Verse] Фонари ...  [Chorus] ...                         ✎ │
│ 96 BPM · A minor · 3:20                                         ✎ │
│                      [ Ещё вариант ]   [ Сгенерировать ▶ ]          │
└────────────────────────────────────────────────────────────────────┘
```

- Переключатель «Песня» или «Инструментал» и поле идеи. Язык текста по умолчанию определяется по идее, как сейчас в аранжировщике (`guessVocalLanguage`).
- Карточки движков: только установленные. Рекомендованный отмечен, у нескачанных — ссылка на страницу «Модели». Для песни: ACE-Step (быстро) и YuE2 (целая песня с вокалом). Для инструментала: Stable Audio 3 (секунды) и ACE-Step.
- «Написать промт» вызывает помощника и показывает результат карточками. Каждую можно поправить. «Ещё вариант» переписывает заново с другим зерном.
- «Сгенерировать» переключает движок через оркестратор, если нужно, и отправляет задачу тем же путём, что формы на страницах движков. Затем переходит на страницу движка, где трек появляется в ленте.
- Флажок «сразу»: промт пишется и генерация запускается одной кнопкой, карточки показываются уже как параметры запущенной задачи.

## 4. Помощник промтов

### 4.1 Где живёт

Отдельный процесс `prompt-assistant`: маленький FastAPI-сервер в своём uv-проекте `external/prompt-assistant` (transformers + torch, CPU-сборка по умолчанию). Бэкенд управляет им как сервером сэмплов на CPU: запускает при первом запросе, останавливает после простоя, проксирует `/api/assistant/*`. В оркестратор движков он не входит и движки не выгружает.

Почему не внутри sa3-server. Помощник нужен и тогда, когда Stable Audio не установлен, а окружение sa3-server тянет torch с CUDA и Flash Attention ради движка. Отдельный проект проще ставить и обновлять, и он не зависит от весов Stable Audio.

### 4.2 Модели

| Модель | Размер | Зачем |
|---|---|---|
| `Qwen/Qwen3.5-2B` | 4,3 ГБ | По умолчанию. Та же, что у помощника Stable Audio. Пишет по-русски и по-английски. |
| меньшая модель на ~0,5–1B | ~1–2 ГБ | Для слабых машин; конкретную выбрать замером качества текстов (раздел 8). |

Скачивание и удаление — на странице «Модели», новый раздел «Помощник промтов», тем же механизмом, что веса Stable Audio (кэш Hugging Face). Настройки: модель, устройство (процессор или видеокарта), потоки, время до выгрузки.

### 4.3 Инструкции

Набор системных инструкций хранится в репозитории, рядом с сервером (`external/prompt-assistant/prompts/`), по файлу на задачу. Для каждой задаёт формат ответа в JSON, чтобы разбор не зависел от вольностей модели:

- `sa3-music`, `sa3-instrument`, `sa3-sfx`, `sa3-oneshot` и `sa3-classifier` — перенос инструкций из апстримного `reprompt.py`, с указанием источника и лицензии (MIT). Ответ: `{"tags": "..."}`.
- `yue2-song` — новая. Ответ: `{"style": "жанр, настроение, инструменты, тип вокала", "lyrics": "[verse]\n...\n[chorus]\n..."}`. Метки и порядок секций — в формате, который YuE2 понимает сейчас; длина текста под 2–4 минуты.
- `ace-song` и `ace-instrumental` — запасной вариант для ACE-Step, когда его модель не загружена, а запускать движок пользователь не хочет. Ответ в полях `create_sample`.

Ответ проверяется: JSON разбирается, длина и обязательные поля сверяются, при ошибке — одна повторная попытка с подсказкой модели, затем ошибка в интерфейсе.

### 4.4 API помощника

```
POST /v1/write   {task, idea, language?, instrumental?, seed?}  -> {fields..., took_ms}
GET  /v1/models  -> [{id, installed, loaded}]
GET  /health
```

Генерация одной задачей за раз; повторный запрос ждёт в очереди. Стриминг токенов в первой фазе не нужен.

## 5. Движки: откуда берётся промт и как запускается задача

| Движок | Промт | Запуск |
|---|---|---|
| ACE-Step | `POST /api/ace/v1/create_sample {query, instrumental, vocal_language}`; движок должен быть запущен (его модель — часть движка). Если не запущен и пользователь не хочет переключать, — помощник с `ace-song` / `ace-instrumental`. | `release_task` в «кастомном» режиме с `prompt = caption`, `lyrics`, `bpm`, `key_scale`, `audio_duration`, `vocal_language` — как форма страницы ACE-Step в режиме «Кастомный». |
| YuE2 | помощник, `yue2-song` | `generateBatch({style, lyrics, …})` стора YuE2 с его значениями по умолчанию. |
| Stable Audio 3 | помощник, `sa3-classifier`, затем нужная инструкция | `submitJob({task: 'text', prompt: tags, duration, …})`, автоматические теги страницы Stable Audio не добавляются повторно. |

Для запуска режим использует существующие сторы и API страниц движков, без нового бэкенда генерации. Параметры, которых нет в ответе помощника (шаги, CFG, длительность для Stable Audio), берутся из значений по умолчанию соответствующей страницы.

## 6. Выбор движка

Рекомендация по умолчанию:

- Песня: ACE-Step, если установлен; иначе YuE2.
- Инструментал: Stable Audio 3, если скачана `medium` или `small-music`; иначе ACE-Step с `instrumental = true`.
- На Mac и без CUDA `medium` не предлагается (как и сейчас).

Выбор пользователя запоминается (localStorage) отдельно для песни и инструментала. Карточка показывает, сколько примерно займёт генерация и что придётся выгрузить работающий движок.

## 7. Где в интерфейсе

Варианты:

1. **Первый экран главной страницы.** Самый простой вход в приложение; карточки движков и недавние треки остаются ниже.
2. Отдельная вкладка в шапке рядом с движками.

Предложение — вариант 1. Отдельная страница `/idea` всё равно нужна для прямых ссылок; главная показывает тот же компонент.

## 8. Замеры

Qwen3.5-2B, transformers 5.20, torch 2.7.1, Ryzen 9 9950X (16 ядер) и RTX 4080. Теги Stable Audio — апстримная инструкция `Music` (2650 токенов вместе с примерами), около 70 токенов ответа. Песня для YuE2 — короткая инструкция (140 токенов) и 320–500 токенов ответа.

| Где | Загрузка | Теги Stable Audio | Песня для YuE2 |
|---|---|---|---|
| процессор, bfloat16 | 2,4 с | 12 с | 36 с |
| процессор, float32 | 2,6 с | 24–28 с | 71 с |
| видеокарта, bfloat16 | 2,1 с | 2 с | 12 с |

Выводы:

- **bfloat16 на процессоре** вдвое быстрее float32: по умолчанию bfloat16.
- **Устройство «авто»**: видеокарта, когда на ней хватает места (модели нужно около 5 ГБ), иначе процессор. Теги на процессоре — 12 с, текст песни — около 40 с; это терпимо, но видеокарта в 5–6 раз быстрее.
- У Qwen3.5 гибридное внимание (Gated DeltaNet). Его быстрые ядра (`flash-linear-attention`, `causal_conv1d`) есть только для CUDA; на процессоре работает эталонная реализация PyTorch, отсюда скорость.
- **Язык нужно задавать явно.** С инструкцией «пиши на языке идеи» модель ответила по-английски на русскую идею; с «пиши по-русски» — по-русски.
- **Русские тексты у 2B слабые**: грамматические ошибки, нет рифмы. Для песен по-русски нужна модель крупнее: Qwen3.5-4B (9,3 ГБ) или 9B (19,3 ГБ), открытые, Apache-2.0. Проверить в фазе 3.
- **JSON может оборваться** (в одном из прогонов не было закрывающей скобки): разбор должен чинить незакрытую строку и скобку, а при неудаче — повторять.
- Теги Stable Audio приходят в его родном виде с `BPM: N. Length: N seconds` в конце; эти числа разбираются в поля темпа и длительности.

Своя модель ACE-Step (`/v1/create_sample`, 5Hz LM 1.7B) против помощника на одной идее («песня о том, как уезжаешь из маленького города ночным поездом»):

| Кто пишет | Время | Что получилось |
|---|---|---|
| ACE-Step, запрос по-русски | 45 с (с инициализацией) | «финский хип-хоп с губной гармошкой», текст не про поезд |
| ACE-Step, тот же смысл по-английски | 16 с | «голландский фолк-рок», текст с мусором (`Atさせて`) |
| ACE-Step, по-русски, повторно | 21 с | ошибка без данных |
| помощник, Qwen3.5-2B, на процессоре (ACE-Step на видеокарте) | 29–73 с | инди-поп, текст по-русски про поезд и город, держится идеи |

Вывод: своя модель ACE-Step быстрее, но от идеи уходит, а по-русски ненадёжна. Поэтому по умолчанию промт для ACE-Step пишет помощник; модель ACE-Step доступна переключателем «Кто пишет промт». Это отступление от раздела 5. Ещё одна находка: помощник иногда экранирует переносы строк дважды, разбор это чинит.

Размеры моделей (Apache-2.0, без лицензионного соглашения): Qwen3.5-0.8B — 1,75 ГБ, 2B — 4,55 ГБ, 4B — 9,32 ГБ, 9B — 19,31 ГБ.

## 9. Фазы

| Фаза | Содержимое | Результат |
|---|---|---|
| **1. Помощник** | `external/prompt-assistant` (uv-проект, сервер, инструкции Stable Audio и YuE2), бэкенд-модуль по образцу `sfx_cpu.py`, прокси `/api/assistant/*`, раздел «Помощник промтов» на странице «Модели», шаги в setup-скриптах и desktop | `POST /v1/write` из идеи возвращает теги Stable Audio и стиль с текстом для YuE2; модель скачивается и удаляется со страницы «Модели» |
| **2. Страница «Из идеи» с ACE-Step** | компонент поля и карточек, вызов `create_sample`, запуск `release_task` в кастомном режиме, переход в ленту ACE-Step | песня и инструментал из одной фразы через ACE-Step с правкой промта |
| **3. Stable Audio и YuE2** | карточки движков, вызов помощника, запуск задач через их сторы, рекомендации раздела 6 | все три движка из одного поля |
| **4. Режим «сразу» и главная** | флажок «сразу», компонент на первом экране главной, запоминание выбора | одна кнопка от идеи до трека |

Каждая фаза — отдельный коммит или PR, проверяется вживую: идея → промт → трек в ленте, повтор с правкой, остановка помощника по простою.

## 10. Открытые вопросы

1. Где режим: первый экран главной (предложение) или отдельная вкладка в шапке.
2. Нужен ли запасной путь ACE-Step через общего помощника (`ace-song`), или достаточно попросить запустить ACE-Step.
3. Одна модель помощника по умолчанию для всех или своя под каждую задачу (например, меньшая для тегов Stable Audio).
4. Нужно ли сохранять «идею» в параметрах трека в библиотеке, чтобы потом повторить запрос.
